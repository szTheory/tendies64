## 3. Compatibility and K1 coupling

- State version bump is compatible only if the new state version lives on new ids (R3). Bumping v25 in place breaks "preserve identities where semantics unchanged" because it also changes semantics (refusal -> draw).
- Pre-Phase-9 profiles: the 17 ids keep byte-identical digests as long as the guard stays version-scoped and new ids use new tuples. The Phase 9 audit verified 510 digests; reuse that harness as the SC1 check.
- Hidden coupling risks: (1) the same predicate gates acceptance of SET_Z_IMAGE/SET_PRIM_DEPTH and four Z triangle opcodes, so existing refusal-control tests on descriptors 11/12 flip; (2) the invalidation loop clears depth sidecar on any accepted RDRAM write (pipeline.c:269), so CPU/PI/SP write paths now carry depth cost and must be covered by an interleaving test; (3) `rdp_depth_hidden` is zeroed by the importer today (t64_state.c:3002) and documented as excluded (state-container.md:483-487); both docs must change; (4) the K1 note is repeated in STATE.md, machine-contract.md:322,402,550 and PROJECT.md; (5) hashing +2 MiB (blob ~6.3 MB -> ~8.4 MB) raises state-import test cost roughly a third (6.3 MB hash/refusal row = 22x under ASan, F-110; hosted macOS 2.5-3.5x native, F-108), interacting with GATE-01 and every enclosing timeout (compare measured sums, AUTONOMY.md Phase9 lessons); (6) the sidecar is a "logical model, no claim about physical hidden-bit packing" (rdp.md:454-459) and Z modes are explicit software policy (rdp.md:478-484), so VID-07 evidence stays "unit-tested, authored scope"; the hardware cite is the primary-source exponent/mantissa table the spec already pins, recheck it rather than adding any oracle (D5).

## 4. Adversarial pass: how Phase 10 fails or balloons

1. In-place depth flip moves all Phase 8/9 pins and every claim; discovered late = a Phase 9-style fix cycle. Mitigation: R3 plus a pre-flight "all existing ids unchanged" digest check before any hosted push.
2. State bump without a field audit: depth members absent from the stream cannot be seen by self-comparing tests (AUTONOMY Phase9 lesson). Mitigation: completeness flip test over every new member first (RED), then implementation.
3. RUN-07 forces a CLI-contract change (R5), reopening the option-pair matrix and the frozen-file deviation process.
4. Re-pin trap fires per manifest commit; approval scope ambiguous (R6); an automated oversight check already denied one rebind (STATE.md:70).
5. GATE-01 success measured on one noisy sample; Phase 10's own tests eat the margin; a cache-miss timeout loop (R7) can leave main red with no way to self-heal.
6. Test-strength work (VG) can expose real defects (surviving mutants imply untested code, not wrong code, but a failing independent vector would be a bug); budget one fix per VG.
7. Qualification inertia: each phase hard-wires its own 2.1-2.6k-line qualifier (qualify-audio.py 2610, qualify-phase09.py 2295, qualify-rdp-vi.py 2171 lines) and gate.sh private roots; a Phase 10 qualifier by copy-paste is large. Decide early whether Phase 10 qualifies as a delta on the Phase 9 qualifier or a new one; prefer a thin delta that binds only changed ids.
8. Local-first discipline: run `act` Linux compile check (F-102) before any push touching C, and `ctest -N -R` regex counts before accepting plan verify commands (AUTONOMY Phase9 lessons).
