## Decisions taken inside this plan (record in the SUMMARY)

- **Classification is static, outcome is dynamic.** The handshake total H of the RD64B start is computed from the table, so the channel 4 cost cannot depend on the busy state (E itself depends on H). `t64_save_channel4_classify` therefore looks only at the profile kind, the declared TX and RX counts and the command byte: the three exact triples (0x00, 1, 3), (0x04, 2, 8) and (0x05, 10, 1) are VALID and cost `2000n + 188 + 438 + 2000m + 250`; everything else on an EEPROM profile is TIMEOUT and costs `2000n + 188 + 3907`; profiles without EEPROM are ABSENT with the same cost as TIMEOUT. A read while busy is VALID at plan time and answers with the timeout flag at E with no data (named policy; the hardware behavior of a busy read is unknown). Per D-14 and D-18.
- **Status naming.** D-23 names three statuses and D-24 adds a "profile has a device" check without a status. A profile with no device answers a request for any kind with `SAVE_DEVICE_MISMATCH` (the requested kind versus the profile's kind none), which keeps the locked set of three. Values: `T64_STATUS_SAVE_UNKNOWN_DEVICE` 20, `T64_STATUS_SAVE_UNSUPPORTED_DEVICE` 21, `T64_STATUS_SAVE_DEVICE_MISMATCH` 22; plan 09-05 uses values from 23 upward for its own statuses.
- **Section 11 presence.** Section 11 is emitted only when `profile.save_kind` is non-zero, so the stem id stream keeps markers 1 to 10 and every 09-03 literal stays valid; the section 11 body is `u32 kind`, `u32 size_bytes`, `u64 busy_until`, `u32 pi_save_direction`, then the raw storage bytes, all in the new-span class.
- **Reset hook.** `t64_save_reset_machine_state` (blank fill, deadline 0) runs at create and at the same reset site as `t64_si_reset_machine_state`, so a successful replacement restores a blank device (D-25 device half). The replacement-table matrix, the refused-admission rows and the table text are plan 09-05; this plan only pins create, direct reset and one successful replacement.
- **CPU store budget needs no change.** Any 32-bit store outside RDRAM already reserves one extra event (`cpu_successor_extra_event_budget` default rule), which covers the PI read-length start; a characterization case pins it instead of editing the pinned CPU path.
- **No new scheduler event pair.** SRAM DMA reuses `(T64_DEVICE_PI, T64_PI_EVENT_COMPLETE)` and EEPROM has no event, so the closed ledger of 09-01 and the membership list stay unchanged; any difference is a defect to explain.
