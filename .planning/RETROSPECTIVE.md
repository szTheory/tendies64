# Tendies64 retrospective

## Milestone: v1.0 — Verified Headless Core

Planning completion, not a software release. Six phases and73 source plans
cover48 current requirements;25 requirements remain open for later milestones.

### What was built

A rights/provenance and six-outcome harness foundation; one deterministic,
observable machine; transactional ROM admission; cleared authored IPL3/hello;
scoped VR4300 and fetched RSP; separate RDRAM A/B and T1 profiles; and original-
evidence, classification and exact artifact contracts. Claims remain bounded
by profiles/builds/fixtures and do not imply hardware accuracy or broad support.

### What worked

Native/refusal/determinism controls and exact inherited inventories prevented
silent regression. Full-entry positive controls exposed defects that setup-only
refusals missed. Exact archived executable/context pairs and one C classifier
make historical evidence reviewable without relabeling or replaying it. Separate
source completion, execution completion and passing preserve real blockers.

### What was inefficient

First real tool/guest entry came too late in several slices. Mirrored encoders,
misread instruction/address fields, helper-only acceptance and unreached test
functions produced misleading early signals. Repeated full source pre-use and
per-case source copies added host overhead; the measured safe reductions retained
one independent source audit and removed duplicate work. Source-seal and generated
bytecode failures caused avoidable full-gate retries. Long report handoffs and
manual fingerprint/path transcription consumed time after execution was complete.

### Patterns and lessons

- Before a long build/run, exercise actual authored startup, successful admission
  and one canonical tick through the real consumer, then negative controls.
- Decode pinned instruction bytes and capture the first exception plus previous
  retirement before diagnosing an address or changing bus/boot behavior.
- Audit source/tool/lock/assets before compilation; inspect actual composition
  after compilation; retain exact executable/binding before activation or rebuild.
- Never reconstruct a lost historical binary or count a failed first use as
  execution. Preserve unknowns and acquire new, separately identified evidence.
- Use actual saved formats early; closed public fields and fully resealed
  inventory/image mutations must reach the intended guard from a valid baseline.
- After adding a production file/changing a sealed function, run its cheap exact
  source/object/body checker before broad suites. Run post-review rights/PII
  preflights; all Python inspection uses-B or PYTHONDONTWRITEBYTECODE=1.
- Keep completed native semantic evidence when only host/provenance inputs change.
  Reverify changed owners and archive identity; do not repeat fuzz for metadata.
- At milestone close, use one bounded delta-verification wave for stale earlier
  reports, backed by current complete inherited tests and integration evidence.
  Do not replay completed phases or suppress genuine source changes. Exclude
  mutable lifecycle trackers from source coverage while retaining real contracts.
- Capture CLI fingerprint JSON and programmatically copy exact covered paths/digest
  into reports; avoid hand-transcribing long lists or retrying fragile patch hunks.
- Before moving lifecycle records, scan consumers for active-path dependencies.
  The RSP evidence reader needed a fixed, unambiguous active/archive lookup;
  its cheap real-table relocation control belongs in the normal test inventory.
- Keep parent bookkeeping local to the orchestrator. Require a concrete delta,
  saved result and remaining command from long handoffs; inspect artifact progress
  before interrupting productive work. Reconcile partial work before inline repair.

## v1.1 planning discovery lesson

The plan initializer treated advisory `*-RESEARCH.md` notes as complete phase
research and selected the adversarial memo before the canonical implementation
research existed. Use `*-OPTIONS.md`/`*-CHECK.md` for decision notes, reserve
`NN-RESEARCH.md` for the implementation research, and inspect the initializer's
resolved artifact path before reusing it. This cheap discovery check caught
the false reuse before planning or a long suite.

The pre-commit privacy scan caught generated plan execution-context references
containing the runtime's absolute home path. Normalize installed workflow and
template references to `@$HOME/.codex/...` before commit, then run the actual
privacy scanner. No waiver or public-history repair is needed when the cheap
pre-commit check runs before staging/publishing the plans.
