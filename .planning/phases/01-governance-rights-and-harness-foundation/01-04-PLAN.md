## Phase Goal

**As a** maintainer, **I want to** run one gate command that enforces the provenance, rights and determinism
rules and drives a runner skeleton that classifies every outcome correctly, **so that** no emulator code
lands before the rules that govern it exist and are proven to fail when broken.

<objective>
Add the decision-record and CI layers of the walking skeleton:
- The ADRs and policies ROADMAP success criterion 1 requires (numbering follows RESEARCH, plus 0007 for the copy policy).
- The CONTEXT A-1 exact-path rule that keeps core code out until ADR-0002 is accepted.
- The hardened CI workflow and its static checker.

All checks run as CTest tests labeled `repo`, registered in this plan's own `tools/repocheck/CMakeLists.txt` and
picked up by the root tools glob. This plan never edits `scripts/gate.sh`. Delta from CONTEXT's gate step list:
these checks run inside the ctest step, so each check's registration lives with its owner.

ADR-0002 stays `proposed` here. Plan 01-08 accepts it from the pre-registered spike criteria, or stops and escalates
on a switch (CONTEXT A-3).
Output: check-docs.sh, ADRs 0000-0007, two policy files, ci.yml, check-ci-yml.sh, CTest registration.
</objective>
