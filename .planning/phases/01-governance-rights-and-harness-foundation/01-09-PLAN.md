**As a** maintainer, **I want to** run one gate command that enforces the provenance, rights and determinism
rules and drives a runner skeleton that classifies every outcome correctly, **so that** no emulator code
lands before the rules that govern it exist and are proven to fail when broken.

Output: schema engine, `t64-manifest-check`, the manifest and schema, 25 seeded manifest files, the require-fixtures
driver, the gate CI block, and the allowlist feed.
</objective>

<interfaces>
Manifest document: `{"schema":"t64.manifest","schema_version":1,"entries":[...]}`.

Non-forbidden entry, required keys:
- `id` (`[a-z0-9][a-z0-9-]*`, at most 64)
- `source` {`repo` (github https URL), `revision` (40 lowercase hex), `path`}
- `build` {`recipe` (non-empty), `toolchain` (array, minItems 1)}
- `sha256` (64-hex or null)
- `size` (integer at least 0, or null)
- `profile`
- `source_rights` and `binary_rights` (`authored-here|cleared|pending|forbidden`)
- `distribution` (unique subset of `commit|artifact|build-only|local-only`)
- `rights_evidence`
- `notices` (array; key required)
- `expected` {`kind` (`self-checking|spec-derived|hardware-derived|differential|regression-pin`), `source`, `revision`}
Optional: `path` (under `fixtures/`) and `capture_provenance`.

Forbidden entry: `id`, both rights `forbidden`, `forbidden_reason`, `notices`, `profile`, and `distribution` as an empty array. No `sha256`, `size`, `build`, `source`, `expected` or `path`.

Schema keyword subset: `type required properties additionalProperties(false only) enum const items minItems maxItems uniqueItems minLength maxLength pattern(POSIX ERE, regcomp REG_EXTENDED|REG_NOSUB, ^...$) minimum maximum oneOf`. `oneOf` is used only for the entry shape, chosen by `binary_rights`. Annotations: `$schema $id title description`. Anything else is `M-SCHEMA-KEYWORD` with exit 2.

`t64-manifest-check [--schema PATH] [--require-fixtures] [--emit-allowlist FILE] [--root DIR] MANIFEST`. Options come before the file. Output `RULE <id> <entry-id or pointer>: message` and a summary `manifest: entries=N permitted=P present=Q skipped=S errors=E`. When clean, it also prints `ok <file>`. Exit 0, 1 or 2. Rules:
- Schema: M-JSON, M-SCHEMA-REQUIRED (names the JSON pointer), M-SCHEMA-TYPE, M-SCHEMA-ENUM, M-SCHEMA-PATTERN, M-SCHEMA-ADDITIONAL, M-SCHEMA-LENGTH, M-SCHEMA-ITEMS, M-SCHEMA-RANGE, M-SCHEMA-ONEOF, M-SCHEMA-KEYWORD.
- Cross-field: M-ZERO-ENTRIES, M-DUP-ID, M-FORBIDDEN-DIGEST, M-FORBIDDEN-REASON, M-NULL-DIGEST (null only for pending), M-BYTES-NOT-PERMITTED, M-PATH, M-DIGEST-MISMATCH, M-FIXTURE-ABSENT (only with --require-fixtures), M-HW-PROVENANCE, M-TOOLCHAIN-PIN.
`--emit-allowlist FILE` writes `path<TAB>sha256<TAB>manifest:<id>` for authored-here/cleared entries that have a path and a sha256 and whose distribution includes `commit`.

Seeds use `run-expect.sh --ext .json`. `tests/seeded/run-require-fixtures.sh` lives outside the seed directory.
</interfaces>
