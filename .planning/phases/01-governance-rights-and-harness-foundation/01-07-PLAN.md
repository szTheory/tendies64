<interfaces>
`t64-result-check` (exit 0 ok, 1 invalid or harness-error, 2 usage). Options always precede the file argument:
- `result FILE`.
- `suite --inventory INV FILE`.
- `seal --inventory INV --out FILE RESULT...`.
- `identity FILE`: validates each result line and prints `fixture_id<TAB>profile_id<TAB>build_id<TAB>evidence_tier<TAB>outcome`.
It prints `ok <file>` on success. Diagnostics are `RULE-ID path[:line]: message`. A suite failure also prints `outcome=harness-error detail=suite-truncated` or `detail=inventory-mismatch`.

Result rules:
- `R-JSON`.
- `R-UNKNOWN-FIELD`, `R-MISSING-FIELD`: the exact key sets from result-protocol.md.
- `R-SCHEMA`.
- `R-VERSION`: schema_version is not the integer 1.
- `R-TYPE`.
- `R-ENUM`: evidence_tier allows `smoke regression-pinned unit-tested self-checking-fixture emulator-differential hardware-derived synthetic`.
- `R-DETAIL-OUTCOME`.
- `R-NOT-CANONICAL`.
- `R-SYNTHETIC-STAMP`: tier synthetic, profile synthetic-stub and a `+synthetic` build must be all present or all absent.
- `R-NULL-RULES`.

Suite rules: `S-TRUNCATED`, `S-INVENTORY`, `S-DUPLICATE`, `S-ORDER`, `S-EMPTY`. The suite record is `{"case_count":N,"inventory_sha256":"<64hex>","schema":"t64.suite","schema_version":1}`. `inventory_sha256` is the SHA-256 of the INVENTORY bytes. INVENTORY is sorted (LC_ALL=C) fixture_ids, one per line, LF-terminated.

Seed directories use `tests/seeded/run-expect.sh` (plan 01-05) with `--ext ".json .jsonl"`. `tests/seeded/suites/INVENTORY` is a support file, not a seed, under that extension rule.
</interfaces>
</context>
