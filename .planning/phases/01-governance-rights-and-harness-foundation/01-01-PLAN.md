rules and drives a runner skeleton that classifies every outcome correctly, **so that** no emulator code
lands before the rules that govern it exist and are proven to fail when broken.

<interfaces>
Facade (`core/include/tendies64/t64_facade.h`; includes only `stdint.h` and `stddef.h`; a header comment states it is provisional per CONTEXT A-1, with the API freeze in Phase 10):
- `typedef enum { T64_STOP_BOUND = 1, T64_STOP_HALT = 2 } t64_stop_reason;`
- `typedef struct { t64_stop_reason reason; uint64_t tick; } t64_advance_result;`
- `typedef struct t64_facade_ops { t64_advance_result (*advance)(void *inst, uint64_t bound_tick); size_t (*drain_guest_log)(void *inst, uint64_t *tick_out, uint8_t *buf, size_t cap); } t64_facade_ops;`
- `const char *t64_core_identity(void);` is defined by the stub and returns the literal `tendies64-core-stub`.
- Semantics: `advance` runs guest time up to and including `bound_tick`. It returns `T64_STOP_BOUND` with `tick == bound_tick`, or `T64_STOP_HALT` with the halt tick. `drain_guest_log` returns queued guest-log bytes in emission order with their record tick, and returns 0 when empty. No global state: everything lives in `inst`.

`tools/common`:
- `t64_sha256_init`, `t64_sha256_update`, `t64_sha256_final` and `t64_sha256_hex`. The message length is encoded explicitly big-endian, and no struct is ever hashed.
- `t64_utf8_valid(buf, len, &bad_offset)` per RFC 3629. It rejects overlongs, surrogates, values above U+10FFFF, bytes F5-FF and truncated sequences.
- `t64_jsonw_*` is a bounded canonical writer into a caller buffer. It emits object, array, string, integer (only within plus or minus 2^53-1), null and bool. Keys must be strictly ascending in unsigned byte order per object, or the call returns an error. Strings are validated with `t64_utf8`. Only `"`, backslash, `\b \t \n \f \r` and other controls below 0x20 (as lowercase `\u00xx`) are escaped. There is no whitespace, and the output ends with one LF.

Gate step names used by later plans: `banner`, `sh-n`, `configure`, `build`, `ctest`, `summary`. Plan 01-03 adds `lint-selftest` (before configure) and `core-lint` (after ctest). Plan 01-09 adds the single `CI=true` block.
</interfaces>
