<interfaces>
`scripts/ci-review.sh RUN_ID [--repo OWNER/NAME] [--append FILE] [--finding "id|finding|taken/declined|reason"]` (POSIX sh; repo defaults to `szTheory/tendies64`).
- Requires gh auth. Refuses when the run status is not `completed`.
- Run fields: `head_sha`, `event`, `conclusion`, `created_at`, `run_started_at`, `updated_at`.
- Per job, from `.../runs/<id>/jobs`: queue `started_at - created_at` and run `completed_at - started_at`, via `--jq fromdate`. Step durations come from `.steps[]`.
- Prints a human table and the derived numbers: wall (created to updated), critical path (max over jobs of queue plus run), and the slowest step.
- `--append FILE` adds one row at the end of the `## Runs` table. `--finding` adds one row at the end of the `## Findings` table, which is the last section of the file. Existing rows are never edited or removed.

`docs/ci-reviews/LOG.md` layout (CONTEXT: one row per reviewed run plus a Findings table):
- A header with the append-only rule, the review policy, the column definitions, and the line `Phase-1-base: <40-hex>`. That value is `git rev-parse origin/main` recorded before the phase's first push, so verification can enumerate the phase's pushed SHAs as `git rev-list <base>..origin/main`.
- The review policy (AUTONOMY section 2): every completed CI run for any pushed SHA gets a Runs row, including red runs. A dated deferral row (same leading `| date | run id |` columns, with the reason) is allowed only when a run's data cannot be read. The first run's row is the VER-04 phase-gate minimum.
- Commits that change only `docs/ci-reviews/LOG.md` carry `[skip ci]` in their message, so recording a review never triggers another run that would itself need a review. Every code-bearing commit triggers a run, and that run is reviewed. The rights and PII scans still run locally before each such push.
- The header follows the plan 01-04 writing rule: no line starts with `Tendies64 ` and contains the whole words accurate, compatible or supports.
- `## Runs`: `| date (UTC) | run id | sha (12) | event | conclusion | wall s | critical path s | gate-linux queue/run s | gate-macos queue/run s | slowest step |`.
- `## Findings`, last: `| id | run id | finding | taken/declined | reason |`, with ids `F-NNN` unique.
</interfaces>
