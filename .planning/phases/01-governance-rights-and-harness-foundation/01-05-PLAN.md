<interfaces>
Parser (`tools/common/t64_json.h`):
- An arena of nodes (object, array, string, integer, bool, null). Default limits: input 1 MiB, depth 16, string 4096 bytes, nodes 4096. A `t64_json_limits` struct can raise them.
- `int t64_json_parse(const uint8_t *buf, size_t len, const t64_json_limits *lim, t64_json_doc *out, t64_json_error *err)`. `err` carries a byte offset and a category from the closed set: `syntax`, `trailing-comma`, `comment`, `bom`, `control-char`, `invalid-utf8`, `bad-escape`, `lone-surrogate`, `float`, `exponent`, `leading-zero`, `negative-zero`, `int-range`, `duplicate-key`, `depth`, `size`, `string-length`, `nodes`, `trailing-data`.
- Helpers: `t64_json_get(obj, key)`, `t64_json_check_keys(obj, allowed, n_allowed, required, n_required, &bad_key)`, and `t64_json_u64_string(node, &out)`, which accepts strings matching `0|[1-9][0-9]*` up to 18446744073709551615.
- Writer extension: `t64_jsonw_node(w, node)` emits a parsed tree canonically.

`t64-json-canon FILE` prints canon(FILE). `t64-json-canon --check FILE` exits 0 when the file is canonical, 1 otherwise (prints `NOT-CANONICAL FILE`), and 2 on a parse error (prints `JSON-<category> offset=N`).

`tests/seeded/run-expect.sh --tool "<command words>" --dir DIR [--ext ".json .jsonl .md"]`:
- It reads `DIR/EXPECT.tsv`: columns `file`, `exit`, `rule_id`, `needle`, with `#` comments and an optional empty needle.
- The seed set is every regular file directly in DIR whose name ends in one of the `--ext` extensions (default `.json .jsonl .md`), excluding `EXPECT.tsv`. Other files (for example `INVENTORY`, `README`, `*.sh`) are support files, not seeds.
- It fails on zero rows, on a seed-set file not listed in EXPECT.tsv (`UNLISTED <file>`), and on a listed file that is missing (`MISSING <file>`).
- For each row it runs `<tool> DIR/<file>` and checks the exit code, that the output contains rule_id, and the needle when present. It prints `ok|FAIL <file> <rule_id>`.
- Rows whose expected exit is 0 use rule_id `ok`, and the tool must print `ok`.
</interfaces>
