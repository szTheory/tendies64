Rust check, in the container, with no crates and no cargo: `rustc --edition 2021 --crate-type=lib --emit=metadata -o /tmp/<class>.rmeta <file>`. Every twin starts with `#![no_std]` and `#![forbid(unsafe_code)]`. The exception is `admission.rs`, which is also compiled with `--test` (the test harness needs std). It uses `#![cfg_attr(not(test), no_std)]`, keeps `#![forbid(unsafe_code)]`, and is compiled for metadata without `--test` to prove the no_std form.
Container: `docker run --rm --network none -v "$PWD":/src:ro -w /src rust:1.91 ...` (rustc 1.91.1, gcc, GNU binutils and mawk; Linux C lint runs in the same image). Record the image repo digest and the container `uname -m`.
Admission parser: `int t64s_admit(const uint8_t *buf, size_t len, size_t limit, t64s_admit_info *out)`. It detects byte order from the first 4 bytes (z64 `80 37 12 40`, v64 `37 80 40 12`, n64 `40 12 37 80`; format facts). It requires `len >= 4096`, `len <= limit` (64 MiB) and `len % 4 == 0`. It returns ok-z64, ok-v64, ok-n64, too-small, too-large, unknown-order or misaligned (outcome codes 0-6 in that order). The Rust twin has the same contract and a `#[test]` table.
Fuzz (rule b): a fixed seed with xorshift64, 2,000,000 mutations, plus boundary sizes 0, 1, 3, 4, 4031, 4032, 4033, limit-1, limit and limit+1. Built with `-fsanitize=address,undefined -fno-sanitize-recover=all -g`. Inputs are in memory only. Nothing ROM-like is written to disk.
Differential fuzz (CONTEXT A-2's Rust admission parser):
- The same xorshift64 generator, seed, mutation schedule and boundary sizes are defined identically in `fuzz_admission.c` and in a `#[test] fn differential` inside `admission.rs`. Both generate the same 2,000,000 inputs in memory.
- Each side prints `outcomes: <c0> ... <c6>`, the per-outcome counts, and `fnv1a64: <hex>`, the FNV-1a 64 checksum over the sequence of one-byte outcome codes.
- The Rust side runs in the container via `rustc --edition 2021 --test -O admission.rs` and then the test binary.
- `run-spike.sh --registered` compares both lines. A mismatch is a registered finding recorded in RESULTS.md. It is not a switch trigger: rule (b) concerns memory safety of the C parser only.
Sanitizers on the Rust parser are not run. Building Rust with ASan/UBSan needs `-Zsanitizer`, which is nightly-only, and the pinned image ships stable rustc 1.91.1 [INFERENCE: not verified in this session]. The parser is `#![forbid(unsafe_code)]`, so memory-unsafety in it is excluded by construction, short of compiler or core bugs.
Harness amendment protocol (W-2): only `run-spike.sh` may be amended after registration; corpus and admission files never are.
- An amendment is a dated `## Amendment N (YYYY-MM-DD)` section appended to PREREG.md. It states the harness bug, the reason, and the new SHA-256 of run-spike.sh.
- The amendment is committed BEFORE the re-run.
- `--registered` verifies run-spike.sh against the hash in the latest amendment, or the original if there is none, and every other file against the original table.
- RESULTS.md lists every run-spike.sh hash used (original and amended) and which run produced the reported table.
