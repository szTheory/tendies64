**As a** maintainer, **I want to** run one gate command that enforces the provenance, rights and determinism
rules and drives a runner skeleton that classifies every outcome correctly, **so that** no emulator code
lands before the rules that govern it exist and are proven to fail when broken.

Add the result layer of the walking skeleton. A synthetic guest behind the facade is driven by `t64-runner-synthetic`.
`t64-supervisor` classifies the run, and the gate's ctest step checks one positive and one negative control against
independently derived golden canonical results. Then the classification is extracted into a pure, fully unit-tested
precedence function, and the contract is written down (CONTEXT "Runner, outcomes and negative controls").

Plan 01-11 completes the 19-case control matrix, the inventory and the suite controls. Plan 01-07 adds the result consumer.
Output: runner sources, two controls with goldens, a classifier unit test, and the result-protocol spec.
</objective>

<interfaces>
Synthetic script grammar v1 (`*.t64s`, UTF-8 text, LF, at most 1 MiB, lines at most 4096 bytes):
- Line 1 is exactly `t64-synthetic 1`. Blank lines and lines starting with `#` are ignored.
- `log <tick> <text>`: escapes `\n`, `\\`, `\xHH`.
- `logx <tick> <hh> ...`: raw hex bytes.
- `end <tick> <directive>`: exactly one, as the last non-comment line. This plan's directives are `quiesce` and `spin`. Plan 01-11 adds `hang abort segv exit0-no-result exit7` and `logrep`.
- Ticks are non-decreasing decimal u64. Any grammar violation makes the runner exit 2 with no report.

Runner `t64-runner-synthetic`: the caller passes `--slice TICKS`. The supervisor appends `--fixture PATH --bound TICKS --log-limit BYTES --report PATH --capture PATH`. Drive loop: `target = min(tick + slice, bound)`, `advance(target)`, drain into the capture with `write(2)` (stops writing at log-limit, keeps counting), stop on HALT or when `tick == bound`, then write the report and exit 0.

Report (text, at most 512 bytes, exactly five lines in order): `t64-report 1` / `stop_reason guest-bound|guest-halt` / `guest_tick <u64>` / `log_bytes_total <u64>` / `end`.

Supervisor `t64-supervisor`: `--identity synthetic --result PATH --meta PATH --work-dir DIR --wall-ms N --bound TICKS --log-limit BYTES --fixture-id ID --fixture PATH --fixture-sha256 HEX --expect-pass N [--capture-out PATH] -- RUNNER [ARGS...]`. Phase 1 accepts only `--identity synthetic`.

Canonical `t64.result` v1:
- Keys, sorted: `build_id, counts, detail, evidence_tier, fixture_digest, fixture_id, guest_tick, log_digest, outcome, profile_hash, profile_id, schema, schema_version, state_digest, stop_reason`.
- `counts` keys, sorted: `fail_reported, log_bytes, log_bytes_total, log_lines, pass_reported, unhandled_exception_lines` (JSON integers).
- `schema` is "t64.result", `schema_version` is integer 1, and `guest_tick` is a decimal string. Digests are 64 lowercase hex characters. `state_digest` is null in Phase 1.
- Synthetic stamp: profile_id "synthetic-stub", build_id "0.0.0+synthetic", evidence_tier "synthetic". profile_hash is the SHA-256 of the 73 bytes `{"profile_id":"synthetic-stub","schema":"t64.profile","schema_version":1}` followed by one LF.
- For harness-error and missing-fixture: log_digest null, all counts 0, stop_reason "none", guest_tick "0". fixture_digest is the actual SHA-256 when the fixture was read, otherwise null.
- The non-canonical `run-meta.json` carries wall_ms, the raw wait status, host OS name and `t64_core_identity()`.

Precedence (first match wins) with the closed detail enum and exit codes:
1. harness-error (exit 1): `usage`, `exec-failed`, `supervisor-signalled`, `wall-backstop`, `runner-signalled`, `runner-exit-nonzero`, `no-result`, `report-invalid`, `fixture-digest-mismatch`, `inventory-mismatch`, `suite-truncated`, `unclassified`. The last three are produced only by suite consumers and the defensive default.
2. missing-fixture (13): `fixture-absent`.
3. guest-fail (10), in this order: `log-over-limit`, `log-invalid-utf8`, `fail-reported` (a line starting `FAIL `), `output-after-done` (any line after `Done!` that is not an unhandled-exception line), `count-mismatch` (`Done!` seen and PASS count != expect-pass), `verdict-incomplete` (guest-halt, non-empty output, no `Done!`).
4. boot-fail (11): `empty-output`.
5. timeout (12): `guest-bound` (bound reached, no `Done!`).
6. pass (0): `positive-match`.
Lines split on LF, and a final unterminated line counts as a line. An unhandled-exception line contains `unhandled exception` (ASCII case-insensitive). These are counted and tolerated after `Done!`.

Matrix `tests/controls/matrix.tsv` (TAB-separated; `#` header): `id script expect_pass bound wall_ms slice_a slice_b fixture_mode fixture_sha256 outcome detail exit`. Goldens live at `tests/controls/golden/<id>.json`, and scripts in `tests/controls/scripts/`. Per CONTEXT A-6, both directories are directory-owned corpora.

## Trust Boundaries

| Boundary | Description |
