## Phase Goal

**As a** maintainer, **I want to** run one gate command that enforces the provenance, rights and determinism
rules and drives a runner skeleton that classifies every outcome correctly, **so that** no emulator code
lands before the rules that govern it exist and are proven to fail when broken.

<objective>
Complete the negative-control matrix CONTEXT locks: positive, wrong counts, failure after Done, deleted fixture,
tampered digest, truncated verdict, non-UTF-8 and over-long output, spin, empty output, abort, segv,
exit0-no-result, hang, dropped inventory case and truncated suite. Each case asserts an exact outcome, runs twice at
two slice sizes, and compares canonical bytes. Phases 3 and 4 replay this matrix against the real core.

Added within Claude's Discretion: positive-unhandled (ADR-0004), fail-reported, empty-bound, exit-nonzero (a valid
report with exit 7) and log-flood-backstop (RLIMIT_FSIZE, RESEARCH A2).

The locked precedence order is unchanged. `fail-after-done` uses a non-FAIL line after `Done!`, so it reaches
output-after-done instead of fail-reported (checker W-1).
Output: 17 new cases on top of plan 01-02's two, INVENTORY, live suite controls, README and the spec update.
Scripts and goldens are directory-owned corpora (CONTEXT A-6).
</objective>

New grammar:
- Directives: `hang` (nanosleep loop forever inside advance), `abort`, `segv` (`raise(SIGSEGV)`), `exit0-no-result` (`_exit(0)` before any report), `exit7` (valid report, then exit 7).

- Runner flag `--ignore-log-limit` (test-only).
- New matrix columns `runner_flags` (`-` for none) and `log_limit` (default 65536).
