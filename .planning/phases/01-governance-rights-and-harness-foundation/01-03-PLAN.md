## Phase Goal

**As a** maintainer, **I want to** run one gate command that enforces the provenance, rights and determinism
rules and drives a runner skeleton that classifies every outcome correctly, **so that** no emulator code
lands before the rules that govern it exist and are proven to fail when broken.

<objective>
The determinism layer of the walking skeleton, and PROF-07 in full (CONTEXT "Determinism lint (PROF-07) and CI").
Layer 1 is a POSIX sh + awk source scan that explains violations. Layer 2 is authoritative: it compiles each core
object with fixed flags and checks sections and undefined symbols against an allowlist. A 19-seed corpus proves every rule.

Measured deltas from CONTEXT, per RESEARCH (measurement wins):
1. The Layer-2 flags add `-D_FORTIFY_SOURCE=0`.
2. `allowlist.txt` gains a 4th column `os`, with `bzero` allowed on Darwin only.
3. Mach-O leading underscores are stripped before comparison.
4. Size-zero sections are ignored, and `nm` type `C`/`c` symbols are a separate failure.

The allowlist's `ADR/date` column cites ADR-0006 as text. Plan 01-04 writes that ADR in the same wave, and its
check-docs required set guarantees the ADR exists by phase end. No build or runtime dependency exists between the two
plans, so no depends_on edge is needed. The core compile hardening flags are already in the root CMakeLists (plan 01-01).
Output: the two-layer lint, rules.txt, allowlist.txt, the `tools/lint/selftest/` corpus (directory-owned, CONTEXT A-6)
and the gate steps.
</objective>

<interfaces>
`core-lint.sh` modes:
- No arguments: both layers over `core/**/*.c` and `*.h`. Headers get Layer 1 only.
- `--root DIR`: the same over DIR.
- `--files F...`: the same over the named files. Plan 01-08's spike uses it.
- `--selftest`: the corpus plus controls.
Output lines: `RULE-ID path:line: message (hint: ...)` for Layer 1, `RULE-ID path: message (hint: ...)` for Layer 2, and a final `core-lint: files=N violations=M`. Exit 0 clean, 1 on violations, 2 on usage or tool error.

`rules.txt` line format: `ID|layer|meta|description|hint`. meta is `yes` for rules proven by a dedicated control instead of an EXPECT seed: `L1-ZERO-FILES`, `L2-COMPILE`, `L2-W-COMMON` (the lint flags include `-fno-common`, so a common symbol can only come from a precompiled object).

`allowlist.txt` line format: `name|why|ADR/date|os`, with `#` comments. Initial rows: `memcpy`, `memmove`, `memset`, `memcmp` (os any, `ADR-0006 2026-11-09`) and `bzero` (os Darwin, why "Apple clang rewrites memset(p,0,n)"). `malloc` is never allowed.

Layer-2 compile line, one object per `.c` in a mktemp dir: `${CC:-cc} -std=c17 -O2 -fno-common -fno-stack-protector -fno-pic -U_FORTIFY_SOURCE -D_FORTIFY_SOURCE=0 -Icore/include -c FILE -o OBJ`. `lint-objects.sh --objects OBJ...` checks precompiled objects only; the selftest uses it for the common-symbol control and the gate never does.

Seed format: each `tools/lint/selftest/bad_*.c` starts with `/* EXPECT: ID [ID...] */`. `good.c` starts with `/* EXPECT: PASS */`. Every listed id must appear in the output. Extra ids are allowed, because arch and compiler differ per runner.

Seeds: 19 `bad_*.c` plus `good.c`. Each must survive `-O2` (RESEARCH Pitfall 5: non-static functions that return or store through volatile).
</interfaces>
