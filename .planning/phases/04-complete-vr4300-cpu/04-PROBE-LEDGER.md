Canon referral: privilege escalation, input/path/injection and generic privacy/retention concerns belong to the configured security review plus existing rights/PII/provenance tooling, not invented prohibition records. This native C project has no ESLint surface. Copyright/asset/source stops are already explicit AUTONOMY/D2/D4 authority and remain hard. They are not softened into a generic judgment warning.

Precision keeps only bespoke evidence/claim transparency, collapsed into four overlapping owner-intent constraints:
1. Selected prepared state, vector, clock, cache and LL/SC policy must not be presented as measured N64 silicon behavior.
2. Generic IEEE arithmetic tests must not be presented as VR4300 hardware or broad compatibility qualification.
3. Test expectations must not be described as independently sourced when produced by the implementation or another emulator; native evidence must name its actual provenance/tier.
4. Complete private CPU coverage must not be claimed from native-only evidence, reduced membership, aggregate summaries or unreached required members; local-use permission must not be presented as public distribution clearance.

These are non-authoritative judgment-tier review flags. Under AUTONOMY's explicit autonomous soft gate, retain unverified-prohibition flags and recommend claim review without inventing a human acknowledgment/acceptance checkpoint. Actual deterministic failures, rights/tool/source gaps and publication stops remain blocking. No wired descriptor is fabricated for a C test that the prohibition engine does not support.
