## COP1 arithmetic and state model

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| Pinned, adapted Berkeley SoftFloat 3e subset | Mature integer implementation of binary32/binary64 IEEE arithmetic and conversions; exact upstream release and BSD-3-Clause source notice verified | Generic IEEE results do not implement VR4300-specific E traps, FS handling, FCR31 rules, or FR register mapping; upstream rounding, tininess, and flags use mutable globals | COP1 seam plus selected common arithmetic sources; BSD-3-Clause provenance per copied file -- Risk: explicit-context adaptation and transitive source closure | Rec if the audited binary32/binary64 closure can be context-threaded without ambient state |
| Tendies64-owned integer binary32/binary64 implementation | Direct per-instance API and VR4300 semantics; no copied-code license/provenance burden | Larger correctness burden for rounding, subnormals, NaNs, arithmetic, conversions, and independent expected values | COP1 arithmetic and conversion modules -- Risk: subtle IEEE errors and a wide validation surface | Rec if SoftFloat's context adaptation or audited closure proves too invasive |

**Rationale:** Prefer the pinned SoftFloat subset, conditional on finalizing its exact dependency closure before any project copy. Pin the official [`ucb-bar/berkeley-softfloat-3` Release 3e commit `f74b1e48110ac3a27dd49b787d164e55e42d81d1`](https://github.com/ucb-bar/berkeley-softfloat-3/tree/f74b1e48110ac3a27dd49b787d164e55e42d81d1) (John Hauser, 2018-01-26), not moving `master`; the official author's [Release 3e archive](https://www.jhauser.us/arithmetic/SoftFloat-3e.zip) has SHA-256 `21130ce885d35c1fe73fc1e1bf2244178167e05c6747cad5f450cc991714c746`, and its generic `source/` plus `source/include/` files match this commit after line-ending normalization. The commit's [`COPYING.txt`](https://github.com/ucb-bar/berkeley-softfloat-3/blob/f74b1e48110ac3a27dd49b787d164e55e42d81d1/COPYING.txt) grants the Regents' three-condition BSD terms for Release 3e and each source file, which is on the existing allowlist; before copying, record the exact selected generic binary32/binary64 operation, conversion and helper files, inspect each file's notice against this pin, and create the required per-file `BSD-3-Clause` provenance entries. Do not copy target-specific x86/ARM/RISC-V specializations or unrelated formats/build files. The upstream API's `softfloat_roundingMode`, `softfloat_detectTininess`, and `softfloat_exceptionFlags` are mutable globals (optional TLS is still ambient and shared by same-thread interleaved instances); replace them in the selected closure with an explicit operation context carrying rounding mode and raised IEEE flags, using the manual's fixed tininess rule, and return result bits plus flags. Keep only immutable `static const` lookup data at file scope; keep FPRs and FCR31 in per-machine CPU state. Separate `core/t64_cop1.c` instruction, register, FCR31, and trap behavior from a raw-integer `t64_softfloat` arithmetic seam; SoftFloat must never own FCR31. The pinned NEC manual U10504EJ7V0UMJ1 (7th edition, August 2000; [PDF](https://hack64.net/docs/VR43XX.pdf), SHA-256 `b7c1900f1707a4b238ebd82af1669e9628e4df4875ceabfa012a9d95b4716b75`) specifies FR/FPR mapping in pp. 208–210 §§7.2.1–7.2.3; FCR31 fields, cumulative flags, last-operation causes, FS flush table and four rounding modes in pp. 211–215 §7.2.4, Figures 7-2/7-3 and Tables 7-2/7-3; generic exception results and VR4300-specific deviations in pp. 236–244 §§8.1–8.2.7, Tables 8-1/8-2 and footnotes; and that VR4300 E leaves only the E cause bit set in p. 631 Appendix B.1.5. In particular, FCR31 has C bit 23, FS bit 24, Cause E/V/Z/O/U/I at 17:12, Enables V/Z/O/U/I at 11:7, Flags V/Z/O/U/I at 6:2, and RM at 1:0; E has no enable or flag and always traps. The CPU layer must implement QNaN/denormal-source and invalid-format E cases, conversion-to-integer overflow/Inf/NaN E cases, destination suppression on enabled/E exceptions, sticky masked exception flags, FS result-flush choices, and FR=0 paired versus FR=1 independent registers. Add independent bit/rational-derived expected vectors for single and double across all four rounding modes, boundary and negative operands, subnormals/FS, signed zero, infinities, quiet/signaling NaNs, comparisons, conversion boundaries, and FCR31 E/unchanged-destination cases; derive values from the manual or independent arithmetic calculations, never SoftFloat under test or another emulator's output. The upstream provides generic IEEE algorithms only; it does not establish VR4300 revision-specific quirks or hardware conformance.
