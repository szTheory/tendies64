## Transaction contract

Capture is explicit opt-in. Default cap64MiB, permitted cap1byte through256MiB, checked uint64 arithmetic for every file plus manifest byte; invalid/missing/duplicate flags refuse before guest startup. A successful requested A/V bundle must contain nonzero actual video and audio data; empty/missing/zero/truncated files, incomplete DMA expectations at the requested terminal condition or missing metadata refuse finalization. Preserve the old noncapture behavior.

Walk the supplied target parent components with directory FDs and no-follow semantics; reject symlink components, dot-dot, empty basename, special files and unsupported platforms. Open and retain the actual parent directory FD. Create a uniquely named sibling stage exclusively with mode0700, and create each relative stream/file with exclusive no-follow operations beneath stage-owned FDs. Bound names and counts. No path concatenation can escape those directory descriptors.

Write actual copied packet bytes with an EINTR/short-write loop, validate lengths, close/flush all stream files, write/validate/close manifest last, fsync files and stage directories, and commit stage to target by Linux renameat2 with RENAME_NOREPLACE or macOS renameatx_np with RENAME_EXCL relative to retained parent FDs. Confirm platform support before starting the guest; unsupported/no-safe-primitive returns host failure. Do not emulate no-replace with exists-then-rename or link/unlink of directories. Existing supervisor atomic_write replaces destinations and is unsuitable here.

The final successful manifest is visible only inside the fully committed bundle. Before commit, any error/termination leaves no target created by this attempt; cleanup only this attempt's verified stage with descriptor-relative operations. On abrupt death a private stage may remain, never a final bundle. If no-replace commit loses a race, leave the winner untouched. Finish all fallible validation and required fsync work before rename; after successful commit perform no fallible step that changes a completed bundle into a reported failure. Document that this is atomic process-visible publication, not a power-loss durability guarantee. Host failure may stop further advancement but must report actual guest progress already reached, never rewind it or invent more ticks.
