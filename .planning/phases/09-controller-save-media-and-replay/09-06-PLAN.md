## Resolution of the CORE-02 reading (recorded before any task)

- The scheduler order is tick then sequence, first in first out (D-02). No class rank, no new policy string. The matrix does not test that this order is correct for any hardware; it pins it as regression behavior and shows it is independent of how the host partitions the advance. A tie that is consistently wrong in every schedule passes; the spec and claim say so (adversarial M4a, D-36).
- Quantum: descriptor 12 refuses a quantum other than 1 and a ratio other than 1:1 (09-01). The unit is "RSP issue opportunities equal to guest ticks". The only documented statement is that another quantum or ratio is a new profile. The sentence that results differ only for CPU and RSP races had no test and is not written anywhere (D-04, adversarial M4c). The quantum reaches state identity through `profile_digest` and no `t64.result` key is added (K10).
- MI: MI pending is set synchronously inside the producing device's event handler and sampled by the CPU at the start of its next step (core/t64_cpu.c:2175-2180). MI is therefore ordered through its producers' events. It is not a scheduled device and this plan adds no MI event or hook.
- Mutants (K5): two of the locked mutants are not usable as worded. A handler that reads the machine tick instead of the event tick is equivalent because dispatch sets the machine tick first (core/t64_scheduler.c:349-352). A sequence taken at commit instead of reserve is equivalent while commit refuses a stale reservation (core/t64_scheduler.c:157-161) and the CPU re-reserves a stale successor (core/t64_cpu.c `cpu_commit_preflighted_successor`). An SI completion derived from the per-advance budget cannot be written literally because the advance bound is a local of `advance_time_bound`, and the per-advance event budget equals the SI read tail of 4,096 ticks at the canonical profile, so that variant is equivalent unless the budget is edited in memory. The realized mutants below keep each intent, are non-equivalent by construction, and two controls (an equivalent mutant that must survive, a non-compiling mutant that must be invalid) prove the driver classifies correctly. This realization is recorded in the CONTEXT amendment K17 ("Amendments from plan checking", D-36), which names `si-completion-from-event-budget`, `cpu-successor-stale-sequence` and the two controls `control-equivalent-handler-tick` (must SURVIVE) and `control-no-compile` (must be INVALID); it is not an in-plan deviation and not a silent change (CONTEXT rule, K5, K17).
- D-36 also lists "later state import at a mid-tick stop". Export and import do not exist before 09-08 and 09-09 (dependency conflict). That row is handed to 09-09.1 (CONTEXT amendment: mid-tick state import is owned by the 09-09.1 boundary matrix) with this plan's mid-tick recipe (see handoffs); it is not dropped.
