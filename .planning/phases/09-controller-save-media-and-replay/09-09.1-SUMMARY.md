## OPEN ISSUES FOR THE ORCHESTRATOR (read first)

1. **CORE-04 is not marked complete.** The matrix, mutants, sweep, campaign, liveness list and audit are delivered, but one finding bounds what "exact" means: the v25 state does not carry the RDP combiner block (the combine mode, its valid flag, the environment, fog and blend colors, the key registers) or the RDP memory-coverage table, although the filter-v9 family behaves on them (`t64_has_rdp_combiner_profile` is true there; the digest and the container hash them only for the combiner, blender and depth profile ids). The importer zeroes them. Consequences observed: a pending triangle packet cannot continue equal (every triangle needs the combine mode), and a VI scan-out that reads coverage marks written by the RDP produces a different retained packet after an import (first difference: `source_bytes` 8 against 16 in the second packet). The canonical state is frozen (F1), so this is a design decision for 09-10 or Phase 10 (carry the members under a new state version, or declare the family out of scope for RDP-heavy states). Rows B05, B06 and B07 use builders that do not depend on these members and say so; nothing was weakened to hide it. `requirements-completed` is empty for this reason.
2. **The audit scan sees 72 of 472 reachable members.** It matches `->member`, `).member` and `].member`; a nested value access `machine->device.member` names the device only. Scalar members reached that way (for example `machine->rdp.render_y` as a bare field) are not in the list. The sweep, the campaign and the liveness list cover accepted states, the audit alone does not. Extending the scan is mechanical but adds an unknown number of rows; left for 09-10.
3. **Importer rules added or found (two production edits, both in `core/t64_state.c`):** the RDP continuation-event rule (commit `5377896`) and the render-extent rule (commit `f2a81b5`). The review plan should read both against `core/t64_rdp.c` `validate_fill_store` and `core/t64_rdp_raster.c` `t64_rdp_triangle_bounds`.
4. **Accepted by design, recorded:** dropping the (SP, RSP issue) event of B03 and B04, and dropping or skewing the (INPUT, SUBMITTED) event of B16, is accepted by the importer and the machine returns from a bounded advance (the plan expected `DEVICE_EVENT_MISSING`). An active SP DMA without an RSP event is likewise accepted; the source never produces it except at sequence exhaustion. If review wants it refused, the rule needs a source-derived discriminator for a legitimately wedged RSP.
5. **Cost.** 33.2 s native in the gate preset (target about 25 s); 631.8 s under ASan against a TIMEOUT that this plan raised from 600 to 1800 s with the reason recorded in `core/CMakeLists.txt` (hashing a 6.3 MB container several times per input, multiplied about 22 times by instrumentation). The full matrix is a native option (`T64_STATE_MATRIX_FULL=1`, 18.2 for the boundaries suite, of which 2.1 for the mid-tick case s for the boundaries and mid-tick cases) and is not set under ASan.
6. **Not pushed.** No hosted run exists for this plan; the Linux pre-flight (Ubuntu 24.04 cc from the act image) caught two `-Wshadow` errors before any push and was run clean on the three changed C units.
7. K13: cumulative Phase 9 gate names are 45 of about 45 (44 through 09-09 plus `harness.state-field-use-audit`); this plan adds exactly that one name.
