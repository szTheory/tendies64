**The authored title runs through the relocated installed package in three consumer cases (short, long and shifted scenarios with the save image read through the API, the persistence round trip with a no-import control, and the refused ROM's blank frames), all compared with generated independent literals and with two separately labeled sets of recorded pins.**

## Accomplishments

- `installed.consumer.title`: the short scenario completes at tick 3,693,938 with 3 frames, 2 audio packets, the 20-byte transcript and the 32,768-byte save image (exported through `t64_machine_save_export`, compared byte for byte and by SHA-256 with the oracle); its four values equal the runner-recorded pins, so the consumer's final digest (`57b683df...`) equals the digest of the runner's raw-capture run (the cross-run-kind equality DR-34 moved here). The long scenario of 12 fields (a run the runner cannot make, its guest cap is 4,000,000 ticks) completes at 13,078,313 with 12 frames, 4 audio packets, transcript and save equal to the literals. The shifted scenario (first 3 fields) equals the shifted literals and differs from the long literals at checkpoint 1 (log line "shifted differs at checkpoint 1"). No packet of an accepted scenario is the blank frame, so a blank screen is distinguishable.
- Consumer-recorded pins, recorded once with `--print` from the long run and written to the section `consumer` of `fixtures/title/title.runner-pins.json` under the label "consumer-recorded pin, not independent" (source "plan 12-05 installed.consumer.title"): completion tick 13,078,313, stop reason `GUEST_COMPLETION`, final state digest `151bf84028782ead7a1265bf9d9d77917fdadfcd94bf0ee6dcb38314baad6b34`, 12 packets. The values are the same for slices of 4,096, 16,384 and 65,536 ticks, and are compared in `title` and in the long run of `title-persist`. The same four values are written into PIN-IMPACT (the checker requires the cited record to hold the ticks and digests).
- `installed.consumer.title-persist`: the long run's exported save image is imported into a fresh instance (admit, import, no input events, run to tick 3,878,126): the three frames (restored position 60, 44, press count 2) and the 17-byte boot transcript equal the persist literals, the save is unchanged, and a control run without the import shows the fresh-boot frame, which is not the restored frame (a missing restore fails the comparison).
- `installed.consumer.title-refused` (DR-34): the refused ROM under the short script to tick 5,000,000 gives 4 video packets, every one the blank digest (printed "blank"), 0 audio packets, 0 transcript bytes, no authored completion (stop at the bound) and a save export equal to the blank save digest. The case also checks the blank digests against zero bytes with the consumer's own SHA-256.
- `scripts/check-consumer-literals.py` now generates and checks both headers. Before it trusts the oracle file it recomputes: the blank frame and blank save digests (zero bytes), each transcript SHA-256, each save image from its nonzero ranges, the SHA-256 of every input script, the first long and shifted difference, and the refused section (blank, no audio, no completion, empty transcript). Seventeen seeded cases (wrong runner label; the consumer label reading "independent"; a missing or foreign consumer section; a flipped long checkpoint digest in the header and in the oracle file; a changed event tick in the header and in the script; a blank digest and a blank save digest that are not zero bytes; refused expectations that are not blank; a blank frame inside a scenario; a runner tick and a consumer digest missing from the cited record; a wrong schema) are each reported with their own text.
- The per-case ROM variable, the case table, `cases.txt`, `PHASE12_TESTS`, the preflight rows (`^installed\.consumer\.` 31, `^installed\.consumer\.title` 5 with the fixture closure) and the labels (`installed;phase12`) are registered once for the three names.

### Choices and observations (not defects)

**3. Shape of the pins file.** DR-07 describes the sections `runner` and `consumer`; the file written by plan 12-04 is the runner record at the top level (the runner test and the 12-04 acceptance read `label` and the four values there). The consumer record is the nested object `consumer`; plan 12-08's reader must take the runner values from the top level and the consumer values from `consumer`.

**4. Shifted scenario as a 3-field prefix.** The plan requires the shifted frames to differ from the long literals at the first moved field; the case runs the first 3 fields (equal to the shifted literals, leaving the long literals at checkpoint 1) instead of the whole 14.1 million tick run, which would have cost about 2 s more. The full shifted run belongs to the pump equality of plan 12-08.

**5. `installed.consumer.title-persist` costs 2.55 s, not the projected 0.9 s.** The real export needs the whole long run. An image built from the literals would cost about 0.7 s but would not be an export of a run, so the plan's round trip is kept; the figure and the reversal rule (the first candidate to move to a local lane if the cold margin falls under 120 s) are recorded for the 12-06 review.

**6. The 1,000,000 tick slice fails by the consumer's own guard.** The per-advance event budget of the open IPL3 boot ends an advance after about 2,100 ticks, so the loop (the same guard as the composite case: 64 consecutive RESOURCE_LIMIT stops for one target) stops at tick 137,316. This is not a library defect; the default slice is 16,384 ticks (recorded in PIN-IMPACT).

**7. `installed.consumer.literals` COST 0.08 to 0.12** for the 17 added seeds (measured 0.12 to 0.14 s at load 12).
