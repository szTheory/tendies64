# Phase 9 roadmap success criteria map (pre-F2 draft)

Status: draft, written in plan 09-10 before the single fix cycle and before the F2 identity freeze.
It is not qualification evidence. The Pass evidence column is completed by plan 09-11 from the
retained native originals of the exact-SHA run; until then every cell of that column holds the same
pending marker. The tier of every planned claim block is unit-tested or regression-pinned and no
statement of this file says anything about hardware, other emulators or commercial software.

How the map is checked: `build/gate/09-10-criteria-check.py` (untracked) requires every named
CTest name to be registered and listed in the test inventory, every suite to exist in
`docs/spec/phase09-cases.json`, every case name to be printed by the owner binary
`--list-cases` and by the CTest command that runs it, every planned claim pair to be one of the ten
pairs of plan 09-11, and the four criteria and the seven requirement ids to appear. Only registered
CTest names are in the named-test cells; a validation-only name is a case under its registered owner.

The criterion text is quoted from `.planning/ROADMAP.md` (Phase 9, Success Criteria 1 to 4).

## Planned claim blocks

Plan 09-11 writes ten blocks in `docs/claims/phase09.md`, one per (profile id, fixture set) pair of the
column above, in this order: 1 pad poll, 2 EEPROM 4 Kbit, 3 EEPROM 16 Kbit, 4 SRAM, 5 save round trip,
6 save refusals, 7 scheduler order, 8 state round trip, 9 replay mix goldens, 10 replay format. The
profile id of blocks 2 to 5 carries the suffix `-e4k`, `-e16k` or `-s32k`; the others use the stem id.
This draft writes no block and no counted figure.

## Limits carried into the independent review

These are recorded facts, not conclusions, and the review and the goal-backward verification decide
what each one means for the criteria.

- Criterion 3 says "exactly": the exported canonical state is the v25 digest preimage. Plan 09-09.1
  recorded that the RDP combiner block and the RDP memory-coverage table were not part of it; the fix
  cycle of plan 09-10 carries both in the tail of section 8 (the case `rdp-state-carry`, the row B17 and
  the completeness sweep of `v25-reference` pin it), so a state holding a pending triangle packet is
  claimed to continue equal on the composite family. The depth members stay inactive there (decision K1)
  and the Phase 8 audio profile does not hash these members (its digest is pinned and unchanged).
- A run resumed from an imported state ends in a closed harness-error record and never reports a pass
  verdict (plan 09-09); its guest tick, final state digest and log bytes are compared instead.
- Replay `save_init` in the `image` form is verified in process only; the real runner exercises the
  blank form.
- Every timing, tie, busy window and button mapping in the named tests is a named software-profile
  policy of this project, not a measured fact.
