# Pre-registration: Rust-versus-C spike (CONTEXT D1)

Registered: 2026-11-10, in the commit that adds this file. No decision data exists when it is committed. The
results file for this spike must be committed after this one, and `run-spike.sh --registered` refuses to run
unless this file is committed and every frozen input still matches the table below.

## Authority and scope

- CONTEXT D1 requires a time-boxed Rust spike before Phase 1 exits. The pre-registered switch criteria are
  quoted verbatim in `docs/adr/0002-language-build-and-abi.md` (Reversal evidence) and restated as computable
  rules below.
- Spike code lives only under `docs/spikes/`. It is never built by CMake and never lies inside `core/`.
- Source of the decision: only the rules below, applied mechanically by `run-spike.sh --registered`.

### A-2 interpretation, verbatim from CONTEXT

> The Rust spike's "determinism lint equivalent" means: the frozen leak corpus is re-expressed as Rust twins
> and each twin is checked against `#![no_std]` + `#![forbid(unsafe_code)]` compile-time rejection
> (single-file `rustc --emit=metadata`), plus the Rust ROM-admission size/header parser fuzzed under ASan/UBSan.
> The interpretation is recorded in `PREREG.md` before results exist.

One deviation from the literal wording of that last clause is declared here, before any result exists. The
Rust parser is not run under sanitizers (see "Sanitizers on the Rust parser"). In its place the Rust parser
runs the differential fuzz below against the sanitizer-checked C parser, and it is `#![forbid(unsafe_code)]`.

### A-3 action rule

The outcome of the rules below decides what happens to ADR-0002:

- "stay with C17" (no rule triggered): ADR-0002 is accepted automatically, with a Confirmation that cites the
  results file.
- "switch" (any rule triggered): ADR-0002 stays `proposed`. The plan stops and escalates to the owner,
  because a switch rewrites the C stub, the lint and the CMake files. Only "stay with C17" may auto-accept.

## 2. Rule (a)

A leak class triggers the switch only if all of these hold:

1. The class is in the frozen list above. The control and the std-escape probe never trigger.
2. The full C gate lint exits 0 on its C twin on the macOS host and exits 0 on its C twin in the Linux
   container. "Full" means both layers, through `sh tools/lint/core-lint.sh --files <seed>`. The gate is green
   only if both operating systems exit 0, so a class that either one catches is caught.
3. The Rust twin fails to compile: `rustc` exits 1 with an error under the flags above. Any other non-zero
   exit (an internal compiler error exits 101) is an anomaly and is not a rejection.

Any C lint exit other than 0 or 1 (exit 2 is a tool error) is an anomaly and is reported, and it does not
count as "exits 0". Classes added after registration go in a post-registration table in the results file and
cannot flip the decision.

Limit of the evidence, stated in advance: macOS is the local host (arm64). Linux is the `rust:1.91` container,
whose architecture is recorded in the results (aarch64 expected). The ubuntu-24.04 x64 runner is first
exercised by CI in plan 01-13 and is not part of this evidence.

## 3. Rule (b)

Triggered only by an ASan or UBSan report in the C admission parser, attributable to `admission.c` (a stack
frame in that file), found by the registered fuzz. The registered fuzz is:

- Fixed seed `0x2545F4914F6CDD1D`, xorshift64 (`x ^= x << 13; x ^= x >> 7; x ^= x << 17`).
- A boundary sweep of the ten sizes 0, 1, 3, 4, 4031, 4032, 4033, limit-1, limit and limit+1 (limit is
  67108864), each with four header variants (z64, v64, n64, none), then 2,000,000 deterministic mutations in
  four kinds: byte flips inside the header, truncation around the 4096 minimum, extension with a small random
  limit, and random length and header. The exact schedule is the code in `fuzz_admission.c` and, identically,
  in the `differential` test of `admission.rs`.
- Built with `-std=c17 -O1 -g -Wall -Wextra -fsanitize=address,undefined -fno-sanitize-recover=all`, on the
  host compiler, falling back to the container's gcc if the host build fails. The tool that ran is recorded.
- Inputs exist in memory only, each in an exact-size heap block. Nothing ROM-like is written to disk.
- Any failure is recorded with its phase, index, length and FNV-1a 64 input digest, printed by a sanitizer
  death callback. A report with no `admission.c` frame is a harness finding, not a trigger.
- Before the registered fuzz, the harness proves the sanitizer is live: a build with a seeded one-byte overread
  (`-DT64S_SEEDED_OVERREAD`) must be caught and attributed to `admission.c`, or the run stops.

## Differential fuzz definition

The C driver and the Rust `differential` test generate the same 2,000,040 inputs in memory (40 boundary
inputs, then 2,000,000 mutations) from the same generator, seed and schedule. Each prints the lines
`boundary <size>: <four outcome codes>`, `mutations:`, `inputs:`, `outcomes:` (counts for outcome codes 0 to
6) and `fnv1a64:` (FNV-1a 64 over the sequence of one-byte outcome codes). `run-spike.sh --registered`
compares those lines. A mismatch is a registered finding recorded in the results. It is not a switch trigger:
Rule (b) concerns the memory safety of the C parser only.

Outcome codes 0 to 6: ok-z64, ok-v64, ok-n64, too-small, too-large, unknown-order, misaligned. The contract,
including the check precedence, is the header comment of `admission.h`.

## Sanitizers on the Rust parser

Sanitizer fuzzing of the Rust parser is not run. Building Rust with ASan or UBSan needs `-Zsanitizer`, which is
nightly-only, and the pinned image ships stable rustc 1.91.1. Observed before registration, with
`rustc -Zsanitizer=address` in the container: ``error: the option `Z` is only accepted on the nightly
compiler``. The parser is `#![forbid(unsafe_code)]`, so memory unsafety in it is excluded by construction,
short of compiler or core-library bugs. The results record the line `Sanitizers Rust: not run`.

## Amendment protocol (harness only)

Only `run-spike.sh` may be amended after registration. Corpus files and admission files never are.

- An amendment is a dated section appended to this file, headed `## Amendment N (YYYY-MM-DD)`. It states the
  harness bug, the reason, and the new SHA-256 of `run-spike.sh` on a line that begins `run-spike.sh sha256: `.
- The amendment is committed before the re-run.
- `--registered` verifies `run-spike.sh` against the hash in the latest amendment, or against the table above
  if there is none, and every other frozen file against the table above.
- The results file lists every `run-spike.sh` hash used (original and amended) and which run produced the
  reported table.

## Amendment 1 (2026-11-10)

Written after run 1's results were known (RESULTS.md, Decision: stay-c17). The phase code review found the
harness bugs below (review findings WR-21 and WR-22). This amendment changes the harness only. No class, corpus
file, admission file, seed, mutation count, compiler flag or rule threshold changes, and rules (a) and (b) are
evaluated as registered.

Harness bugs:

1. The decision failed open. It printed `stay-c17` whenever rule (a) listed no trigger and rule (b) found no
   report naming `admission.c`. So a fuzz that did not finish still read `stay-c17`: allocation failure (exit
   3), an outcome out of range (exit 4), an `info-consistency: BAD` result (exit 5), a docker failure, or an OOM
   kill. So did a broken C lint (exit 2 on every class, counted as an anomaly but ignored) and a missing
   `rustc` (exit 127). The script never checked that `inputs: 2000040` was printed.
2. Rule (b) attribution matched the bare text `admission.c`. That text also matches the harness file
   `fuzz_admission.c` and any message that names the file without a sanitizer report.
3. The tool that rule (a) measures, the C gate lint (`tools/lint/core-lint.sh`, `lint-objects.sh`,
   `rules.txt`, `allowlist.txt`), is not in the frozen set, and run 1 recorded neither its hashes nor a commit.

Changes:

- The decision has three values. `switch-rust`: rule (a) lists a trigger, or the fuzz exited non-zero with an
  ASan or UBSan report attributable to `admission.c`. `stay-c17`: neither rule fired, and all of these hold.
  The class table has 0 anomalies, so no lint exit 2, no `rustc` exit 127 and no missing row. The container
  reported a `rustc` version. The sanitizer negative control passed. The fuzz ran and exited 0 and printed
  `mutations: 2000000`, `inputs: 2000040` and `info-consistency: ok`, with no sanitizer report text. The Rust
  differential printed the same `info-consistency` line. The lint files match the recorded commit.
  `inconclusive`: anything else, and also any failed lint or `rustc` negative control, even when a rule
  appears to fire (a lint that cannot fail proves nothing either way). `inconclusive` exits 3. A harness error
  after the frozen-input check now prints `mechanical-decision: inconclusive` instead of stopping with no
  decision line.
- A sanitizer report means an ASan `ERROR: AddressSanitizer` line or a UBSan `runtime error:` line.
  Attribution needs a location in `admission.c` itself (`admission.c:<line>`, not preceded by a name
  character), so a frame in `fuzz_admission.c` alone is a harness finding. The same test is used by the
  sanitizer negative control.
- A class row missing from the Linux C results or the Rust results counts as an anomaly.
- `--registered` prints the git commit and the SHA-256 of the four lint files as run.
  The lint is recorded, not frozen. Freezing it would add rows to the table above, which this protocol does
  not allow. This is a disclosed gap in the original registration. Any future spike must freeze the tool under
  test.
- New mode `--decision-selftest`: 27 negative and positive controls run the real decision code on synthetic
  inputs. Each changes one fact of a clean fixture that decides `stay-c17`. Every non-clean condition above
  must yield `inconclusive`. Rules (a) and (b) must yield `switch-rust`. A report in `fuzz_admission.c` only
  must not. CTest runs it as `repo.spike-decision-selftest`. Nothing is built, and no decision data is
  produced.

Direction of the change: compared with run 1's harness, these rules can only turn a would-be `stay-c17` into
`inconclusive`, or a would-be `switch-rust` caused by an unattributable report into `inconclusive`. They
cannot produce `stay-c17` where the original harness would not have.

Not amended, because the protocol forbids changing admission files: `fuzz_admission.c` accepts a malformed
`--mutations` value (review IN-24). The registered run passes no arguments, so it is unaffected.

Known limit, unchanged by this amendment (review WR-23): after its length checks the spike parser reads only
`buf[0..3]`, so rule (b) as constructed could hardly fire. See ADR-0002, "Evidence limits".

The re-run uses the lint as it stands at the re-run commit. That lint has changed since run 1 through
review fixes CR-13 and WR-16, and the results record both versions.
